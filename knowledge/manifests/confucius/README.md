## 为什么没有把五份文件都直接用于回答

《论语》并非孔子亲笔著作，而是孔子及弟子言论的编纂传统，因此正式片段统一使用
`QUALIFIED_FIRST_PERSON`，并保留说话者与篇章定位。

两份 2026 中文阅读版与 Gutenberg #23839 使用同一底本，如果全部启用会造成重复
召回。Internet Archive《四书》文件的内嵌提示明确说明它由自动 OCR 生成，部分
页面估算准确率不足 25%，而且《孟子》等篇并非孔子言论，因此这些文件已进入 R2
和版本数据库，但暂不进入 Agent 的正式回答上下文。

Gutenberg #23839 本身也存在已知录入错误，例如《卫灵公》通行本“其恕乎”被录为
“其怒乎”。本次没有把该错误句作为正式种子片段，而改用《颜渊》12.2 的“己所不欲，
勿施于人”。后续扩展整书切片前，应先与可靠点校本逐章校勘。

## 重新导入

```powershell
npm run db:migrate:local

Get-ChildItem knowledge/manifests/confucius/*.json |
  ForEach-Object {
    npm run knowledge:import:local -- $_.FullName
  }
```

导入是幂等的：相同作品、版本和片段 ID 会被更新，不会重复创建。导入命令会把
原始文件复制到本地 R2 模拟目录，并把书目、版本和片段写入本地 D1。

## 后续扩充建议

1. 补充具有明确底本、校勘说明和使用许可的《论语》中文点校本。
2. 按二十篇及通行章次完成整书切片，并保留“子曰”“有子曰”“曾子曰”等说话者字段。
3. 对理雅各译本建立逐章中英对齐，不把 `ren`、`li`、`junzi` 等概念简单等同于
   Victorian English 译词。
4. 将《大学》《中庸》《孟子》分别建立作品记录；只有明确属于孔子语录传统的材料
   才能进入孔子 Agent 的第一人称回答。
5. Project Gutenberg 元数据只明确相关文件在美国属于公版；生产发布前仍需核验
   部署所在地法律，且不要提供原文件公共下载接口。
